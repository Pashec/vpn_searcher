# vpn_searcher

Сервис на базе FastAPI для быстрого поиска памяток сотрудников, параметров подключения к сети и учетных записей VPN в биллинге UTM5. Включает авторизацию сотрудников, панель администратора для управления учетными записями, персональную историю поисковых запросов и печатную форму памятки.

## Назначение

Штатный клиент utm-admin избыточен по функционалу и медлителен, когда требуется оперативно найти рабочие параметры абонента: номер аудитории, привязанные IP/MAC-адреса, учетные записи VPN с паролями или распечатать служебную памятку при подключении рабочего места.

vpn_searcher предоставляет единый поисковый интерфейс, который выполняет поиск по базе биллинга без ручного переключения режимов и вкладок.

## Основные возможности

* Единая поисковая строка:
  - По аудитории: формат корпус-аудитория (`1-337`, `2-709`) или просто номер кабинета (`709`).
  - По сетевым реквизитам: рабочий IP-адрес (`10.100.0.144`), полный MAC-адрес или его окончание (например, последние 4 знака `77-D0`).
  - По пользователю: фамилия или полное ФИО (`Иванов`, `Иван Иванов`), логин абонента (`iivanov`).
* Интерактивный список кандидатов: при обнаружении нескольких совпадений (однофамильцы или несколько человек в одном кабинете) выводится список с номерами комнат, должностями и телефонами для перехода к конкретной памятке в один клик.
* Аутентификация и безопасность: доступ к поисковым данным защищен авторизацией. Пароли пользователей хранятся с использованием PBKDF2 HMAC SHA-256.
* Панель администратора: создание учетных записей сотрудников, деактивация доступа и сброс паролей при утере.
* Персональная история: каждый сотрудник видит последние выполненные им поисковые запросы с возможностью быстрого повтора.
* Профиль и аватарки: возможность смены пароля и загрузки фотографии профиля (JPEG, PNG, WebP).
* Печать памятки: верстка памятки адаптирована для печати на листе А4 по нажатию кнопки в интерфейсе или сочетанию клавиш Ctrl + P.
* Встроенная консоль диагностики: скрытая панель логов (открывается кнопкой в шапке или клавишами Ctrl + ~) для быстрой проверки ответов биллинга и сетевых задержек без входа на сервер по SSH.

## Стек технологий

* Бэкенд: Python 3.12, FastAPI, Uvicorn
* База данных: SQLite3
* Протокол биллинга: NetUP URFA (клиентский TLS v1, CHAP-аутентификация, кастомный бинарный RPC-протокол, парсинг служебного ODT-документа для извлечения актуальных паролей VPN)
* Фронтенд: Vanilla JS, HTML5, CSS3
* Контейнеризация: Docker, Docker Compose

## Структура проекта

```text
vpn_searcher/
├── app/
│   ├── api/v1/          # Эндпоинты (auth, admin, history, memo)
│   ├── core/            # База данных SQLite, конфигурация, сертификаты URFA
│   ├── schemas/         # Схемы валидации данных (Pydantic v2)
│   ├── services/        # Клиент протокола URFA (сетевой сокет и парсер ODT)
│   └── static/          # Веб-интерфейс (HTML, CSS, JS)
├── data/                # Файл базы данных SQLite и загруженные аватарки
├── tests/               # Набор юнит- и интеграционных тестов
├── Dockerfile           # Образ контейнера
├── docker-compose.yml   # Конфигурация для запуска в Docker Compose
├── run.py               # Точка запуска Uvicorn
├── requirements.txt     # Зависимости Python
└── .env.example         # Пример конфигурации подключения к UTM5
```

## Учетная запись администратора

При первом старте сервиса в базе данных автоматически создается суперпользователь:
* **Логин:** `admin`
* **Пароль:** `admin`
* **Роль:** `admin`

После первого входа рекомендуется изменить пароль администратора в модальном окне профиля.

## Конфигурация (.env)

Подключение к серверу UTM5 настраивается через файл `.env` в корне проекта:

```env
# IP-адрес и порт демона UTM5 (URFA)
UTM_HOST=your_host
UTM_PORT=your_port

# Учетная запись администратора биллинга с правами чтения документов
UTM_LOGIN=your_login
UTM_PASSWORD=your_billing_password
```

## Развертывание в Docker

Для развертывания на виртуальной машине с установленным Docker:

1. Клонировать репозиторий:
```bash
git clone git@github.com:Pashec/vpn_searcher.git
cd vpn_searcher
```

2. Создать файл конфигурации `.env`:
```bash
cp .env.example .env
nano .env
```
Укажите реальный IP-адрес биллинга UTM5 и реквизиты доступа.

3. Запустить контейнер в фоновом режиме:
```bash
docker compose up -d --build
```

Сервис запустится на порту 8000. База данных SQLite и аватарки сохраняются в каталоге `./data` на хосте, поэтому пользовательские данные не теряются при перезапуске или обновлении контейнера.

Остановка сервиса:
```bash
docker compose down
```

Просмотр логов:
```bash
docker compose logs -f
```

## Развертывание на сервере без Docker (Linux VM)

1. Клонировать репозиторий и перейти в каталог:
```bash
git clone git@github.com:Pashec/vpn_searcher.git
cd vpn_searcher
```

2. Создать виртуальное окружение Python:
```bash
python3 -m venv .venv
source .venv/bin/activate
```

3. Установить зависимости:
```bash
pip install -r requirements.txt
```

4. Скопировать и заполнить `.env`:
```bash
cp .env.example .env
nano .env
```

5. Запустить сервер:
```bash
python run.py
```

Для постоянной работы сервиса в фоновом режиме рекомендуется настроить системный юнит systemd:

`/etc/systemd/system/vpn-searcher.service`:
```ini
[Unit]
Description=VPN Searcher UTM5 Staff Service
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/vpn_searcher
ExecStart=/opt/vpn_searcher/.venv/bin/python /opt/vpn_searcher/run.py
Restart=always
RestartSec=5
EnvironmentFile=/opt/vpn_searcher/.env

[Install]
WantedBy=multi-user.target
```

Управление сервисом через systemd:
```bash
sudo systemctl daemon-reload
sudo systemctl enable vpn-searcher
sudo systemctl start vpn-searcher
sudo systemctl status vpn-searcher
```

## Тестирование

Запуск тестов в активном виртуальном окружении:
```bash
pytest -v
```
Юнит-тесты выполняются изолированно с использованием тестового дублера и не требуют прямого сетевого подключения к UTM5. Если боевой сервер биллинга доступен по указанному в `.env` адресу, автоматически выполняются интеграционные тесты реального протокола URFA.
